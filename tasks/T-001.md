# T-001: Fachliches Domänenmodell mit CRUD-API

## Ziel

Fachliches Domänenmodell als Grundlage für die Anwendung, die folgenden Entitäten haben eine Abbildung in der Datenbank und CRUD Endpoints an der API

- Material: (Name, Mengeneinheit (Standard: Stück))
- Lagerort: (Name)
- Verbrauch: (Lagerort, Material, Menge)
- Bestellung: (Lagerort, Material, Menge)

Jede Entität hat einen Fortlaufenden Schlüssel und eine GUID als Key

## Akzeptanzkriterien

- [x] Material, Lagerort, Verbrauch und Bestellung liegen in MongoDB und haben unter `/api` Endpoints zum Auflisten, Lesen, Anlegen, Ändern und Löschen; der Vertrag steht in `docs/api/openapi.yaml`
- [x] Jeder Datensatz hat eine GUID (`id`, Schlüssel in URLs und Verweisen) und eine vom Server je Entität fortlaufend vergebene, unveränderliche Nummer (`number`), die nach dem Löschen nicht wiederverwendet wird
- [x] Ohne Angabe ist die Mengeneinheit eines Materials `Stück`; die Menge ist eine Zahl größer 0, Dezimalwerte sind erlaubt
- [x] Namen von Material und Lagerort sind je Entität eindeutig (409)
- [x] Verweise auf unbekanntes Material oder unbekannte Lagerorte werden abgelehnt (400); verwendetes Material und verwendete Lagerorte lassen sich nicht löschen (409)
- [x] Ohne Anmeldung antworten alle Endpoints mit 401; lesen dürfen alle Angemeldeten, Verbrauch schreiben dürfen alle Angemeldeten, Material, Lagerort und Bestellung schreiben nur ADMIN und MANAGER (sonst 403)
- [x] Der gesamte Ablauf und die Vergabe der Nummern sind gegen ein echtes MongoDB geprüft, auch bei parallelen Anfragen und nach einem Neustart
