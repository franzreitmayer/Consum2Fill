# T-008: Anmeldung und Authentifizierung

## Ziel

Nutzer werden am System authentifiziert und authorisiert. Der Zugriff auf die Anwendung soll durch eine Authentifizierung geschützt werden. Den Anwendern wird die Anwendung ihren Rollen entsprechend angezeigt. Es soll eine lokale in der Datenbank verwendete Anwendung geben und eine Anmeldung via Keycloak als zentrales IAM, via OIDC möglich sein. Der Anwender soll bei Anwendung wählen können ob er sich lokal oder am Idenitity Provider authentifizieren will. Bei der Integration mit Keycloak sollen auch die Benutzer in der Anwendung angelegt werden.

## Akzeptanzkriterien

- [ ] Es besteht ein Datenbankschema, dass die Benutzerdaten reflektiert
- [ ] Für den Anfang reichen die Rollen ADMIN, MANAGER und USER. Ein user hat immer nur genau eine dieser Rollen
- [ ] initial werden folgende User angelegt (username, passwort, rolle): (admin, admin, ADMIN), (manager, manager, manager), (user, user, USER)
- [ ] Fehlt die Authifizierung, erscheint ein Loginscreen. Bei diesem kann zwischen der Anmeldung mit einem lokalen User oder einem User aus dem IAM ausgewält werden, wenn dieses konfiguriert ist
- [ ] in der Anwendung gibt es einen Administrationsbereich, den nur Benutzer der Rolle ADMIN sehen. Dort können die Informationen für die OIDC Integration gepflegt werden.
- [ ] in diesen Administrationsbereich werden auch die lokalen Benutzter gepflegt (CRUD), sowie eine Funktion um das Passwort zu setzen zur Verfügung gestellt.
