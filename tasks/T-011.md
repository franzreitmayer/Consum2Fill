# T-011: Materialstammdaten

## Ziel

Die Materialstammdaten können gepflegt und durchsucht werden. Unterhalb von „Stammdaten“ erscheint eine Aufteilung in Tabs wie im Bereich „Administration“, mit den Tabs „Lagerorte“ und „Material“. Unter „Material“ werden die Entitäten zu Material gepflegt (CRUD), mit demselben Fehlerhandling wie bei den Lagerorten. Die Entität wird um die Attribute Beschreibung und Schlagworte ergänzt. Schlagworte sind eine Auflistung und lassen sich in der Oberfläche wie Tags mehrfach vergeben.

## Akzeptanzkriterien

### Bereich und Rechte

- [x] Unter „Stammdaten“ gibt es die Tabs „Lagerorte“ und „Material“. Zugriff haben ADMIN und MANAGER.
- [x] Die Lagerorte funktionieren im neuen Tab unverändert.

### Material pflegen

- [x] Material kann angelegt, geändert und gelöscht werden. Das Löschen muss vorher bestätigt werden.
- [x] Die Liste zeigt Nummer, Name, Mengeneinheit, Beschreibung und Schlagworte, auch lange Texte ohne Querscrollen.
- [x] Die Mengeneinheit ist im Formular enthalten und ohne Eingabe `Stück`.
- [x] Verwendetes Material lässt sich nicht löschen. Die Meldung der API erscheint, und der Eintrag bleibt.
- [x] Die Mengeneinheit lässt sich nicht ändern, solange ein Verbrauch oder eine Bestellung auf das Material verweist (409 mit Meldung). Der Name bleibt änderbar.
- [x] Ein doppelter Name wird abgelehnt, die Meldung erscheint im Formular.

### Beschreibung und Schlagworte

- [x] Die Entität und `docs/api/openapi.yaml` sind um `description` und `tags` ergänzt. Beide sind optional, ohne Angabe gelten eine leere Beschreibung und eine leere Liste.
- [x] Vorhandene Materialien bleiben lesbar und änderbar und liefern dieselben Standardwerte.
- [x] Die Beschreibung ist mehrzeilig und hat höchstens 2000 Zeichen.
- [x] Schlagworte lassen sich mehrfach als Tags vergeben und einzeln entfernen. Bestätigt wird mit Enter oder Komma, Vorschläge kommen aus den geladenen Materialien.
- [x] Ein Material hat höchstens 20 Schlagworte mit je höchstens 50 Zeichen. Leerzeichen am Rand werden entfernt, Dubletten ohne Rücksicht auf Groß- und Kleinschreibung fallen weg. Die API setzt diese Regeln ebenfalls durch (400). Ein PATCH ersetzt die ganze Liste.

### Volltextsuche

- [x] Ein Suchfeld im Tab „Material“ durchsucht Name, Beschreibung und Schlagworte der geladenen Liste.
- [x] Die Suche ignoriert Groß- und Kleinschreibung und findet auch Wortteile. Bei mehreren Wörtern muss jedes in einem der drei Felder vorkommen.
- [x] Findet die Suche nichts, erscheint ein eigener Hinweis, der sich vom Zustand ohne angelegtes Material unterscheidet.

### Fehlerhandling und Bedienung

- [x] Die gemeinsame Logik für Lagerorte und Material ist herausgezogen statt kopiert.
- [x] Fällt ein Benutzer nach einem Rollenentzug beim Speichern auf „Start“ zurück, erscheint dort eine Meldung, dass die Änderung nicht gespeichert wurde.
- [x] Lade- und Fehlerzustände sind sichtbar, alles funktioniert ab 360 px Breite und per Touch.
- [x] Der Ablauf ist gegen ein echtes MongoDB geprüft, auch mit einem Material, das vor dieser Änderung angelegt wurde.

## Hinweise

- Die Suche läuft im Browser, weil die API ohnehin alle Materialien ohne Paginierung liefert. Vertrag und Datenbank bleiben dafür unberührt, und ein Textindex von MongoDB fände keine Wortteile. Bei sehr vielen Materialien müsste sie auf den Server wandern.
- Das Eingabefeld für Schlagworte lässt sich mit `Autocomplete` aus MUI Core bauen, eine neue Abhängigkeit ist nicht nötig.
