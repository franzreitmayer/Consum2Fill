# T-006: Entwicklung und Debugging im Docker-Container

## Ziel

API und Frontend laufen während der Entwicklung im Container `app`, damit auf dem Host außer Docker und einem Editor nichts installiert sein muss und überall dieselbe Node-Version gilt. Der Produktionsbetrieb mit `docker compose up --build -d` bleibt unverändert.

## Akzeptanzkriterien

- [x] Ein Befehl startet `db` und `app` im Entwicklungsmodus mit dem Quellcode aus dem Repo
- [ ] Änderungen an API-Code starten die API im Container neu, Änderungen am Frontend erreichen den Browser per HMR, auch auf einem Windows-Host (API-Neustart geprüft, HMR über den Vite-WebSocket geprüft; im echten Browser offen)
- [ ] Ein Debugger aus VS Code hält an einem Breakpoint im TypeScript-Code der API im Container (über das Inspector-Protokoll und die Source Map geprüft; aus VS Code selbst offen, dabei auch das Wiederverbinden nach einem Neustart prüfen)
- [x] Der Debug-Port ist nur auf `127.0.0.1` des Hosts erreichbar
- [x] `pnpm check` läuft im Container grün
- [x] Das Produktions-Image und `docker compose up --build -d` verhalten sich wie zuvor

## Definition of Done

- `make check` oder `make docker-check` grün
- Akzeptanzkriterien vom `reviewer` bestätigt
- `PROGRESS.md` und `status` aktualisiert (`/handoff`)
