# T-013: Erfassung von Verbräuchen

## Ziel

Verbrauchtes und zusätzlich angefordertes Material kann erfasst werden. Neben „Administration“ und „Stammdaten“ gibt es das Hauptmenü „Erfassung“, „Start“ entfällt. Unter „Erfassung“ liegt der Bereich „Verbrauch/Bedarf“, in dem die Verbräuche aus T-001 gepflegt werden, mit einem Filter auf den Lagerort, Listen wie in den Stammdaten und CRUD. Die Menge wird im Dialog mit + und − eingestellt. Jeder Verbrauch hält fest, wer ihn erfasst hat.

„Bedarf“ ist ein anderer Name für Verbrauch: Auch angefordertes Material wird als Verbrauch gespeichert. Später kommt unter „Erfassung“ die Bestellung hinzu, bis dahin genügt eine Überschrift statt Tabs.

## Akzeptanzkriterien

### Menü

- [x] Das Hauptmenü zeigt „Erfassung“ für ADMIN, MANAGER und USER, „Stammdaten“ für ADMIN und MANAGER und „Administration“ für ADMIN. „Start“ ist entfallen.
- [x] „Erfassung“ ist für alle Rollen die erste Ansicht. Die Rückfall-Meldung nach einem Rollenentzug erscheint dort.
- [x] Bei 360 px Breite passen alle Menüpunkte ohne Querscrollen und sind mindestens 48 px hoch, gemessen im Browser.

### Liste und Filter

- [x] Unter „Erfassung“ liegt der Bereich „Verbrauch/Bedarf“.
- [x] Die Liste zeigt Nummer, Material, Menge mit Einheit, Lagerort, Datum und wer erfasst hat, die neuesten zuerst.
- [x] Ein Filter zeigt alle oder einen einzelnen Lagerort. Ein gewählter Lagerort ist im Dialog vorbelegt und bleibt dort änderbar.
- [x] Passt ein neuer Eintrag nicht zum aktiven Filter, bleibt das erkennbar.
- [x] Ohne Lagerorte oder ohne Material erscheint ein Hinweis statt eines Dialogs, der nicht ausfüllbar ist. Der Text passt auch für USER, die keinen Zugang zu den Stammdaten haben.

### Erfassungsdialog

- [x] Verbrauch kann angelegt, geändert und gelöscht werden. Das Löschen muss vorher bestätigt werden.
- [x] Material wird per Suche ausgewählt, über dieselbe Suche wie im Tab „Material“. Die Mengeneinheit erscheint neben der Menge.
- [x] Die Menge startet bei 1 und ändert sich mit + und − um 1. − ist gesperrt, wenn die Menge dadurch 0 oder kleiner würde.
- [x] Die Menge lässt sich auch direkt eingeben, mit Dezimaltastatur und deutschem Komma. Beim Rechnen entstehen keine Rundungsfehler wie `0,30000000000000004`.
- [x] Das Fehlerhandling entspricht dem der Stammdaten, ein unbekannter Verweis (400) erscheint im Dialog.

### Erfasst von und Rechte

- [x] `createdBy` mit `id` und `displayName` steht im Vertrag und in den gemeinsamen Typen. Der Server setzt es beim Anlegen aus der Sitzung und übernimmt es nie aus dem Anfragetext. Ein PATCH ändert es nicht.
- [x] Der Name bleibt erhalten, wenn der Benutzer gelöscht wird. Verbräuche von vor dieser Änderung bleiben lesbar und liefern `createdBy: null`.
- [x] Lesen und Anlegen dürfen ADMIN, MANAGER und USER.
- [x] Ändern und Löschen dürfen ADMIN und MANAGER bei allen Einträgen. USER dürfen nur eigene ändern und löschen, sonst antwortet die API mit 403. Einträge ohne `createdBy` dürfen nur ADMIN und MANAGER ändern und löschen.
- [x] Die Oberfläche zeigt „Bearbeiten“ und „Löschen“ nur, wenn sie erlaubt sind.
- [x] Die Rechte der Bestellung bleiben unverändert. ADR 0005 und `docs/architecture.md` sind angepasst.

### Bedienung und Prüfung

- [x] Lade- und Fehlerzustände sind sichtbar, alles funktioniert ab 360 px Breite und per Touch.
- [x] Der Ablauf ist gegen die echte API und ein echtes MongoDB geprüft, als ADMIN, als MANAGER und als USER, auch mit einem Verbrauch, der vor dieser Änderung angelegt wurde.

## Hinweise

- `HomeView.tsx` entfällt. `/api/hello` hat dann keine Nutzung mehr im Frontend, bleibt aber vorerst im Vertrag.
- Der Lagerort-Filter läuft im Browser. Die Verbrauchsliste wächst schneller als die Stammdaten, deshalb sind Filter und Paginierung auf dem Server als T-014 vorgemerkt.
- `RecordAdmin.tsx` sortiert neue Einträge heute aufsteigend nach Nummer ein und braucht für „neueste zuerst“ eine Option. Lagerorte und Material bleiben unverändert.
- Verbrauch und Bedarf sind in den Daten nicht unterscheidbar. Das lässt sich später nicht rückwirkend trennen.
